# 官方插件市场：一期前端与后续接入

## 统一规则

插件各自配置三个维度，使用相同的一步安装和卸载流程。

| 插件 | 可见范围 | 首次安装策略 | 使用要求 |
| --- | --- | --- | --- |
| 法律 | 账号获得法律白名单资格后可见 | 用户安装 | 白名单资格有效 |
| 文献综述 | 所有人 | 默认安装一次 | 文献综述任务使用 Memmy 官方模型 |
| Office | 所有人 | 用户安装 | 已安装 |

三类插件都允许卸载和重新安装。默认安装不表示无法卸载，也不能在重启后自动恢复用户已卸载的插件。文献综述的模型要求只作用于文献综述任务，普通聊天继续使用用户选择的模型。

本期目录均为 Memmy 官方插件。点击“安装”后连续完成下载、应用官方插件声明的权限和启用，不再弹出安装或权限确认。达到真实 active 状态后才表示安装完成。中途失败显示实际状态并允许重试；卸载保留确认。此规则只用于官方目录，不改变通用第三方插件的权限策略。

安装状态与使用要求分开：未安装、安装中、已安装、安装异常。没有官方模型也能查看或卸载文献综述插件。模型要求在详情中说明，不占据插件列表的主要位置。

## 入口与连接的关系

侧边栏保持“连接与工具”，沿用 `/tools` 页面，不增加独立插件入口。

- 应用工具：第一个切换按钮，默认打开。让 Memmy 访问和操作 GitHub、Notion、Google Drive 等应用；使用连接、管理、断开操作。
- 聊天渠道：第二个切换按钮。从微信、Telegram、飞书等聊天应用向 Memmy 发任务、收结果；使用连接、配置、断开操作。
- 任务插件：第三个切换按钮。增加法律、文献综述、Office 等成套任务能力；使用安装、使用、卸载操作。

切换入口参考用户提供的 WorkBuddy 顶部导航形式：图标加文字，未选中项无边框。配色遵循 Memmy 现有主题：选中项复用导航浅绿色底，文字和图标使用深绿色，悬停为更浅的品牌色。不使用横贯页面的下划线页签。

页面顶部显示同一级的三个图标文字切换按钮，下面显示当前目录。三个分类依据用户目的，不依据安装包或连接协议；不再把渠道、应用工具塞进同一页而另开插件市场。三类共用内容宽度、标题说明、刷新、搜索、状态筛选和紧凑列表；工具的业务类别保留为应用工具内的次级下拉筛选。搜索和筛选在应用工具与聊天渠道之间各自保存。

插件列表使用每排三项的紧凑条目、小图标、名称和一句用途、右侧安装或管理操作。视觉沿用 Memmy 记忆页：复用 `memory-panel__header`、标题/说明、刷新按钮和筛选样式；条目使用相同的浅边框、圆角、文字层级和间距，不使用大面积卡片。内容宽度不超过900px时两列，不超过620px时单列；版本、模型条件、能力说明放详情。演示条件收进可展开的“交互预览”区，避免预览控件抢占产品内容。

插件用“安装/卸载”，外部服务用“连接/断开”。安装 Office 不等于授权 Microsoft 365；卸载插件不会操作用户的外部账号连接。现有新手引导仍进入连接页。

品牌不是分类依据：同名 Discord 的应用工具和聊天渠道使用独立目录身份与原有 API；搜索或已连接状态不会把两者合并。法律资格、默认安装和模型要求是条目政策，不决定一级分类。

应用工具和聊天渠道的条目只显示图标、名称及实际连接状态，不逐项重复“连接某账号”等通用说明。宽窗口每行四项，随内容宽度缩为三列、两列、单列。任务插件保留有区分度的用途说明，宽窗口每行三项。

插件详情采用“场景示意图＋简短介绍”：上方柔和主题色背景展示三条具体使用示例，下面一段用途说明，默认安装、模型、账号要求收为简短条件。示例是静态介绍，不是执行按钮；安装和卸载仍由底部明确操作触发。弹窗限制在视窗高度内，正文可滚动，关闭和操作区始终可达。

## 当前分支落地范围

当前 `survey_master` 仅提供文献综述 `0.5.18` 的正式插件包。

- 文献综述：读取 Host 的真实安装状态；一次操作完成安装和启用；持久记录卸载选择。在详情中展示官方模型要求和设置入口。
- Office：全员可见，标记“即将上线”。`upstream/v1.1.5` 的能力尚未打包成插件，因此本期没有虚构可安装产物。
- 法律：白名单接口尚未提供，真实市场默认隐藏。`legal` 的业务代码不能替代账号资格数据。
- 开发交互预览：`?memmyRoute=/tools&plugin-market-preview=1`。显著标注演示，可切换法律资格、官方模型状态，体验插件发布后的安装/卸载。仅开发环境动态加载；不调用真实插件、账号或权限 API。

法律用途来自 `legal/e83d4238` 的劳动用工场景；Office 来自 `upstream/v1.1.5/c13b8887` 的 docx、xlsx、pptx、pdf 技能。它们的插件化不包含在本期前端工作中。

## 后续接入边界

前端目录中的资格参数仅用于界面组织，不是权限控制。正式开放法律和 Office 安装前需补齐：

1. 官方目录接口返回经过当前账号权限过滤的插件，以及 `canInstall`、`canUse`、阻塞原因、版本和真实安装状态；前端不接收白名单用户清单。
2. 法律资格在安装、启用、启动恢复、工具发现和执行时由后端校验。账号退出或切换后重新判定，不能把本机已经安装视作新账号获得授权。
3. 法律、Office 发布包及固定校验值进入官方目录。Office 保持手动安装策略。
4. 文献综述执行链路选择当前账号可用的官方模型，校验实际模型来源和账号归属；覆盖插件推理与 Agent 编排。不能只凭模型名称、登录状态或前端提示认定限制生效。

当前提交未改变实际模型路由；界面展示的官方模型要求与后端强制约束应分开验收。后续接入不应为了文献综述修改全局聊天默认模型。

## 官方模型范围：待确定的执行方案

目前存在两层模型：聊天中的 Agent 使用会话选择的模型；文献综述插件内部的关键词、大纲、正文等调用 Host 的 `model-inference`，当前按全局 Agent 默认分配解析。它们并不会自动保持一致。

建议一期以明确的插件调用作为边界：Host 收到 `literature-review` 的推理请求时，固定选择当前账号的官方模型，不沿用普通聊天所选的自定义模型。没有可用官方模型或额度不足就暂停插件执行，提示登录或处理额度，不静默换成自定义模型。这样能保证插件内部生成使用官方模型，普通聊天和外层任务协调仍使用用户所选模型。

若业务要求理解需求、工具选择、后续反馈等整个流程都使用官方模型，则需单独创建并持久化文献综述任务类型，同时约束 Agent 会话和插件推理。普通聊天中发起时应明确进入该任务，不能只靠文本关键词或模型自行分类。恢复任务、账号切换及续写时也要重新校验。该范围比仅控制插件内部推理更大，尚未在本期实现。
